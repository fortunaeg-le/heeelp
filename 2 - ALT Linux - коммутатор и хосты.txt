КАК ОТВЕЧАТЬ на каждый следующий мой запрос:
- Только команды в блоках кода, без пояснений до и после. Одна машина = один блок кода. Если по ходу надо вставить текст в файл через nano или ответить в диалоге программы — дай этот текст отдельным блоком кода с одной строкой-подсказкой над ним.
- В блоках для Linux между соседними командами ставь отдельную строку из решётки и 41 дефиса. В блоках ESR разделителей нет.
- Делай ровно то, что я прошу в запросе, в том же порядке, каждую команду ровно один раз, без лишних проверок, перезагрузок и «улучшений».

ПРАВИЛА ESR (vESR 1.x):
- Маска в адресах и сетях всегда в виде косой черты и числа из таблицы (адрес/28). Никогда не пиши маску точками (255.x) и обратную маску (0.0.0.x) — ESR их не принимает.
- Порт пишется как interface gigabitethernet и номер вида 1/0/2. Подинтерфейс VLAN — номер порта, точка, номер VLAN.
- Любая настройка — отдельным блоком: в начале вход в режим конфигурации, в конце выход из него полностью, затем применение и подтверждение изменений (команды commit и confirm даются ТОЛЬКО после полного выхода из режима конфигурации).
- На КАЖДОМ интерфейсе, подинтерфейсе и туннеле, где что-то настраиваешь, отключай межсетевой экран ESR на этом интерфейсе, иначе транзит не пройдёт.
- Выход из каждого вложенного раздела — отдельной командой exit.

ПРАВИЛА ALT Linux:
- nmcli и NetworkManager на машинах НЕТ — никогда их не используй. Сеть настраивается только через etcnet: каталог /etc/net/ifaces/ИНТЕРФЕЙС/ с файлами options, ipv4address, ipv4route, resolv.conf; применяется командой systemctl restart network.
- Я ввожу команды руками: пиши коротко. Файл — одной командой echo (несколько строк — echo -e с \n внутри кавычек), без cat <<EOF и без nano, если я не прошу nano.
- Имя хоста — полное (имя.домен), маленькими буквами.

Если понял — ответь одним словом: Готов.

Промт 1

Машина: HQ-SW (Linux). Войди под root. Проверь ip -br link: три порта должны совпадать с таблицей. Если делаешь не первый раз — сначала ls /etc/net/ifaces и удали лишние каталоги от прошлых попыток (например rm -rf /etc/net/ifaces/br0), иначе старые адреса останутся.

Машина: коммутатор (ALT). Схема: на порту коммутатора к роутеру-1 — три VLAN-подинтерфейса с именами вида ПОРТ.VLAN; мост «br + VLAN серверов» = подинтерфейс VLAN серверов + порт к серверу-1; мост «br + VLAN клиентов» = подинтерфейс VLAN клиентов + порт к клиенту-1; адрес управления — на подинтерфейсе VLAN управления. Команды: 1) Полное имя коммутатора через hostnamectl; exec bash в той же строке. 2) cd /etc/net/ifaces. 3) Одной строкой for по трём портам коммутатора (к роутеру-1, к серверу-1, к клиенту-1): mkdir -p каталога и echo -e 'TYPE=eth\nBOOTPROTO=static' в его options. 4) Одной строкой for по трём VLAN (серверов, клиентов, управления): mkdir -p каталога ПОРТ.VLAN (ПОРТ = порт коммутатора к роутеру-1) и echo -e в двойных кавычках четырёх строк TYPE=vlan, HOST=ПОРТ, VID=VLAN, BOOTPROTO=static в его options. 5) mkdir -p двух мостов (br + VLAN серверов, br + VLAN клиентов). 6) options моста серверов: echo -e в двойных кавычках трёх строк: TYPE=bri, HOST='подинтерфейс VLAN серверов пробел порт к серверу-1' (значение HOST в одинарных кавычках), BOOTPROTO=static. 7) То же для моста клиентов: подинтерфейс VLAN клиентов и порт к клиенту-1. 8) В ipv4address подинтерфейса VLAN управления: «IP коммутатора/маска управления». 9) В ipv4route того же подинтерфейса: default via шлюз управления. 10) В resolv.conf того же подинтерфейса: nameserver внешний DNS. 11) systemctl restart network. Пути относительные. Ровно одиннадцать команд.
